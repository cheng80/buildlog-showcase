# 빌드로그 · 소개 사이트 기획서

> 문서 버전: 2.2 · 갱신일: 2026-09-16 · 상태: 구현 반영 기준안
>
> 이 문서는 서비스 **빌드로그**를 알리는 홍보 홈페이지의 기획 정본이다. 실제 서비스의 제품 기획서가 아니다. 서비스 개념의 근거는 사용자의 ChatGPT 기획 대화(`_workspace/chatgpt-project-idea-2026-09-16.md`)이며, 카피와 화면은 `app/page.tsx`에 구현된 내용과 일치한다.

## 1. 소개할 서비스

**빌드로그** — 개발 과정을 공유하는 프로젝트 SNS.

앱, 웹, 게임을 만드는 개발자가 오늘 만든 것을 스크린샷이나 유튜브 링크로 가볍게 올리면, 게시물이 피드에 뜨고 같은 게시물이 프로젝트 페이지에 개발 기록으로 쌓인다. 게시물을 올릴 때마다 프로젝트가 다시 노출되어 만드는 과정 자체가 홍보가 된다.

### 서비스 구조 (3층)

```text
개발자(프로필)
 ├─ 프로젝트 A   ← 상시 페이지: 소개·스크린샷·기술·링크·Release·타임라인
 └─ 프로젝트 B
        ▲
   게시물은 반드시 프로젝트에 연결

  [게시물] 스크린샷 / GIF / 유튜브·쇼츠 URL / GitHub URL + 한 줄
      │
 ┌────┴────┐
 ▼         ▼
피드       프로젝트 타임라인
(발견)     (기록·포트폴리오, 올릴 때마다 피드에 재노출)

피드 = 사용자 게시물 + 공식 카드(오늘의 만들기 주제, 개발 팁·기술 소식 카드뉴스, 이번 주 프로젝트)
     → 사용자가 적어도 피드가 비지 않음
```

| 층 | 내용 | 사용자 요구의 근거 |
|---|---|---|
| 1. 가볍게 올리기 | 입력창 하나. URL을 붙이면 영상·저장소·링크 카드가 자동으로 됨 | "쉽게 올릴 수 있어야 하고 외부 영상 링크도 쉽게. 유튜브 영상로그 만드는 사람이 많다" |
| 2. 프로젝트에 쌓이기 | 게시물과 Release가 타임라인으로 누적, 올릴 때마다 재노출 | "개발로그 연재 시 상위 노출" — 국내 차별점 |
| 3. 피드가 안 죽기 | 공식·자동 카드가 사용자 게시물 사이를 채움 | "게시물이 적어도 죽어가는 느낌이 들어선 안 된다" |

좋아요·저장·팔로우, Featured/Boost 결제, 프로필의 팀 위치(지도)는 부속 기능이며 소개 사이트에서는 화면 속 아이콘과 문구로만 다룬다. 인스타그램은 참고한 UX일 뿐이며 사이트 문구에 다른 서비스 이름을 쓰지 않는다.

## 2. 소개 사이트의 목표 / 제외 범위

- 처음 온 사람이 첫 화면만 보고 **"개발자가 만드는 과정을 올리는 프로젝트 SNS"**라고 말할 수 있다.
- 스크롤하면서 올리기 → 피드 → 프로젝트 페이지 순서로 서비스를 화면으로 이해한다.
- 모든 화면은 HTML/CSS로 그린 실제 서비스 UI 모습이다. 생성형 인포그래픽은 쓰지 않는다.
- 단일 랜딩 페이지. 로그인, 게시, 피드·반응 동작, 결제 등 실제 기능은 구현하지 않는다.

## 3. 타깃

| 사용자 | 사이트가 보여줄 것 |
|---|---|
| 1차: 인디 개발자(개인) | 스크린샷·유튜브 링크 한 줄이 게시물이 되고 프로젝트 페이지에 쌓이는 모습 |
| 1차: 소규모 개발팀·개발사 | 프로젝트 페이지 링크 하나로 진행 과정을 소개하는 모습 |
| 2차: 새 앱·게임을 찾는 사람, 동료 개발자 | 만들어지는 중인 프로젝트가 흐르는 피드 |

## 4. 페이지 구조와 카피

### 섹션

| 순서 | ID | 역할 | 화면(HTML/CSS) |
|---|---|---|---|
| 상단 | `#top` | 이름·이동 | 빌드로그 / 올리기 / 피드 / 프로젝트 / 시작하기 |
| S-01 | `#hero` | 무엇인가 | 제목 가운데 정렬. 아래에 [피드 창: 영상 게시물] → 화살표 → [프로젝트 창: 타임라인, 같은 글 강조] 나란히 |
| S-02 | `#why` | 왜 필요한가 | 문제 3개 카드(기록 흩어짐 / 출시 날 하루 / 일상 글에 섞임), 각 카드 아래 "빌드로그에서는" 답 |

| S-05 | `#project` | 프로젝트 페이지 | 헤더·기술 칩·스크린샷 3장·개발 기록 타임라인 |
| S-06 | `#features` | 기능 | 6개 그리드 |
| S-07 | `#who` | 누구에게 | 3개 카드 |
| S-08 | `#start` | 시작하기 | 3단계 |
| S-09 | `#faq` | 질문 | 4개, 첫 질문 펼침 |
| S-10 | `#closing` | 마무리 | 진한 띠 + CTA |
| 하단 | 푸터 | 이름·이동 | 이름·태그라인, 섹션 링크 7개, © 2026 빌드로그 · 예시 안내, 처음으로 |

### FAQ

| 질문 | 답변 |
|---|---|
| 어떤 프로젝트를 올릴 수 있나요? | 앱, 웹, 게임처럼 직접 만들고 있는 프로젝트라면 완성 전이라도 올릴 수 있습니다. 만드는 과정부터 기록하는 곳입니다. |
| 글을 길게 써야 하나요? | 아니요. 스크린샷 한 장이나 영상 링크에 한 줄만 붙여도 게시물이 됩니다. 새로 만드는 게 아니라 이미 만든 것을 가져오는 방식입니다. |
| 유튜브에 올린 개발 영상도 되나요? | 됩니다. 링크를 붙이면 영상 카드가 되고, 같은 게시물이 프로젝트 타임라인에도 기록으로 남습니다. |
| 다른 SNS와 무엇이 다른가요? | 게시물이 흘러가 버리지 않고 프로젝트 페이지에 순서대로 쌓입니다. 피드는 개발 중인 프로젝트 게시물로만 채워져 프로젝트 소식이 일상 게시물에 묻히지 않습니다. |

화면 속 앱 UI(CSS): 작은 타이머는 상단 라벨 '집중 · 25분', 진행 링과 24:59, 하단 '일시정지 / 종료' 버튼 모양, 영상이면 재생 버튼과 '0:42'. 달빛 정원사는 별·달·픽셀 격자·HUD '밤 3일째 · 물 2'·땅·식물 5개. 레시피 메모는 검색창 '감자, 양파, 달걀', 태그 2개, 레시피 행 2개(감자 달걀전, 양파 볶음밥). 모두 예시 앱의 UI이며 서비스 실적 숫자가 아니다.

숫자(좋아요·팔로워·조회)는 표시하지 않는다. 화면 속 이미지는 CSS로 그린다(팔레트는 `DESIGN.md`).

## 5. 기능 요구사항

- **FR-001 섹션 이동:** 헤더 링크, 히어로 두 링크, 마무리 CTA, 로고·처음으로가 4절 앵커로 이동. 고정 헤더가 제목을 가리지 않음(`scroll-padding-top`). 스크립트 없이 동작.
- **FR-002 서비스 화면:** 게시물 카드, 입력창, 피드, 프로젝트 페이지를 HTML/CSS로 그림. 화면 속 버튼·아이콘·칩은 `span`/`div`로 만들어 포커스되지 않음. 화면 속 글자는 실제 텍스트. 히어로에서 게시물 카드의 글과 타임라인 첫 항목이 같은 문구.
- **FR-003 FAQ:** `details`/`summary` 4개, 첫 항목 기본 펼침, 키보드 동작.
- **FR-004 반응형:** 1440px 히어로는 제목 가운데 + 창 2개 나란히, 올리기·피드·프로젝트는 텍스트·화면 2열(피드는 화면이 왼쪽), 그리드는 3열. 1023px 이하 1열(텍스트 먼저)·그리드 2열·히어로 창 세로. 767px 이하 헤더 2줄·그리드 1열·히어로 왼쪽 정렬. 360·390·768·1440px에서 가로 넘침 없음.

## 7. 공통 규칙

| ID | 규칙 |
|---|---|
| BR-001 | 이미 운영 중인 프로덕트처럼 현재형. 제작 상태·기간·일정 표현 금지. |
| BR-002 | 사용자 수, 반응 숫자, 후기, 가격·무료, 수상 등 확인되지 않은 사실 금지. 예시라는 점은 화면 아래 작은 캡션으로만. |
