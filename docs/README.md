# 프로젝트 쇼케이스 문서 · Lite

**먼저 [소개 사이트 기획서](01_PRODUCT_SPEC.md)를 읽으세요.** 목적·대상·카피·페이지 구조·8개 ASCII 와이어프레임·16개 이미지 생성 프롬프트를 한 문서에서 확인할 수 있습니다.

이 묶음은 `project_team_docs_lite.zip`의 문서·운영 구조를 적용한 **신규 소개 사이트 기획**입니다. 기존 서비스 문서를 이관하거나 실제 서비스 제품 기획을 작성한 것이 아닙니다. 웹사이트·이미지·배포 산출물도 아직 없습니다.

## 구성과 읽는 순서

| 문서 | 역할 |
|---|---|
| [01_PRODUCT_SPEC.md](01_PRODUCT_SPEC.md) | 소개 사이트 기획 정본. 파일명은 원본 규칙을 유지하지만 기획 대상은 홍보 홈페이지다. |
| [02_TECH_SPEC.md](02_TECH_SPEC.md) | Next.js App Router·TypeScript 제작, Vercel 배포, 정적 페이지 구성과 검증 기준. 실제 서비스의 DB·API는 설계하지 않았다. |
| [03_PROJECT_STATUS.md](03_PROJECT_STATUS.md) | 문서 완료 상태, 후속 제작 작업, 미확정 자료, 검증, 인수인계 |
| [04_WORKFLOW.md](04_WORKFLOW.md) | 기획 → ASCII → 시각화 → 제작 → 검증의 작업 방식 |
| [AGENTS.md](../AGENTS.md) | 다음 AI 작업자의 읽기·갱신 경로 |

사람은 README → 기획서 → 기술 전제 → 작업 흐름 순서로 읽습니다. 이어서 작업할 때는 현황 문서부터 확인합니다.

## 원본 구조 적용

원본 ZIP의 파일은 루트에 배치되어 있었지만, 원본 README의 권장 구조인 **루트 `AGENTS.md` + `docs/` 안의 네 정본 문서**를 따랐습니다. UI·ASCII·프롬프트는 기획서에, 검증·인수인계는 현황 문서에 모았습니다.

| 원본의 정보 / 규칙 | 이번 묶음의 반영 위치 |
|---|---|
| 한 줄 정의·목표·사용자·흐름·FR·화면·BR·완료 기준 | `01_PRODUCT_SPEC.md` 1~8절 |
| 기술·데이터·API 정본 | `02_TECH_SPEC.md`; 소개 사이트에 불필요한 항목은 해당 없음으로 명시 |
| 로드맵·작업·상태·검증·인수인계 통합 | `03_PROJECT_STATUS.md` |
| 변경·검증·종료 절차 | `04_WORKFLOW.md` |
| AI 진입점 분리 | 루트 `AGENTS.md` |
| 필요할 때만 추가 문서 생성 | 빈 `plans/`, `decisions/`, `assets/`와 별도 인수인계 파일을 만들지 않음 |

원본의 `improvement_handoff.md`는 원본 팩 자체의 변경 설명이므로 복사하지 않았습니다. 필요한 원칙만 이번 작업 흐름과 현황에 적용했습니다. 원본 파일은 변경하지 않았습니다.

## 전달 형식

기획서는 일반 UTF-8 Markdown으로 단독 열람할 수 있습니다. 문서 간 링크와 작업 구조까지 유지하려면 함께 제공한 `showcase_site_docs_lite.zip`을 풀어 사용하세요.

8개 `WF` 각각에 같은 번호의 인포그래픽용 `IG`와 UI 목업용 `UI` 프롬프트가 붙어 있습니다. 실제 이미지가 필요할 때 원하는 쌍을 사용하면 됩니다.
